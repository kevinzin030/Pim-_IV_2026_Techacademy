## Diretrizes de trabalho

- Manter o Product Backlog priorizado pelo Product Owner.
- Dividir tarefas em entregas pequenas e verificáveis.
- Registrar tarefas no GitHub Issues e associá-las às sprints.
- Utilizar branches para funcionalidades e correções.
- Revisar alterações relevantes por Pull Request.
- Definir critérios de aceitação antes de considerar uma tarefa concluída.
- Atualizar este documento e o planejamento de sprint quando houver mudança de escopo.

## Planejamento detalhado

O backlog, a divisão de requisitos e as datas das sprints devem ser mantidos aqui em arquivos complementares, usando como referência o planejamento Scrum aprovado pela equipe. Evite tratar estimativas iniciais como compromissos imutáveis sem validação.
